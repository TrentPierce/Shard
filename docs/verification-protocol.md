# Verification Protocol

## 1. Overview
Shard uses speculative decoding by letting Scout nodes propose draft token distributions while verifier nodes independently compute reference distributions for the same prompt context. The verifier accepts low-divergence draft positions to reduce end-to-end latency, then deterministically regenerates from the first rejected position so final output quality remains verifier-bounded.

## 2. Acceptance Algorithm
`ACCEPTANCE_THRESHOLD = 0.12` (KL divergence, natural log base).

```text
Input:
  draft_logits[position][vocab]
  verifier_logits[position][vocab]
  draft_tokens[position]

Procedure:
  accepted_prefix = []
  first_reject = None

  for position in 0..draft_length-1:
    p = softmax(draft_logits[position])
    q = softmax(verifier_logits[position])
    kl = sum_i p_i * ln(p_i / q_i)

    if kl < ACCEPTANCE_THRESHOLD:
      accepted_prefix.append(draft_tokens[position])
    else:
      first_reject = position
      break

  if first_reject is None:
    suffix = []
  else:
    suffix = verifier.generate_from(position=first_reject)

  return accepted_prefix + suffix
```

## 3. Threshold Derivation
The threshold was selected from an offline sweep over prompt-response pairs where we measured KL divergence against human-preferred continuation quality. We swept thresholds from `0.02` to `0.25` and chose `0.12` as the operating point where (a) rejection catches high-confidence wrong-token attacks and (b) acceptance rate stays high enough to preserve speculative speedup. Statistically, `KL < 0.12` corresponds to distributions with close mass concentration around the verifier top tokens, which keeps semantic drift low while retaining throughput gains.

## 4. Golden Ticket Protocol
- Audit probability `P = 0.05`.
- A request selected as a golden ticket is fully generated by verifier-only inference (no Scout draft reuse).
- Scout draft tokens are scored against the independent verifier reference.
- Audit score is exact token match percentage over the audited span.
- If a Scout wallet's golden-ticket score is below `Q = 60%`, the wallet is flagged.
- Flagged wallets receive no credits for 24 hours and remain in a forced re-audit path until performance recovers.

## 5. Adversarial Attack Vectors and Defenses
- Plausible-but-wrong draft attack: Scout emits low-entropy logits centered on the wrong token. Defense: KL divergence rises sharply against verifier logits and rejection occurs at the first mismatched position.
- Acceptance-rate gaming: Scout tries to submit only easy prefixes to keep acceptance high. Defense: rolling acceptance windows plus golden-ticket audits tied to wallet-level penalties.
- Timing attack for audit detection: Scout attempts to infer golden tickets from response timing. Defense: constant-path verification envelope, jittered verifier scheduling, and delayed audit label emission so audit/non-audit request timing distributions overlap.
